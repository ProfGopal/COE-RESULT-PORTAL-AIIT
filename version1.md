🏗️ Updated Architecture Blueprint: AIIT Result Portal (Dynamic Excel Upload)
1. System Overview
Frontend (Hosting): GitHub Pages (profgopal.github.io/COE-RESULT-PORTAL-AIIT/). Pure HTML/CSS/JS. Crucially: SheetJS will be used on the frontend to parse Excel files.

Backend (API): Google Apps Script (GAS). Acts as the secure server handling CRUD (Create, Read, Update, Delete) operations.

Database: Google Sheets. The central repository for consolidated student data and passwords.

2. Security & Data Strategy
Zero Hardcoded Data: The frontend contains absolutely no student data. "Inspect Element" reveals nothing.

Client-Side Parsing: To avoid backend timeout limits, the raw Excel file is parsed in the admin's browser using SheetJS before being sent to the database.

Upsert Logic (Overwrite/Update): When the admin uploads a new Excel file, the system checks the Student Enrollment Number (SEN). If the SEN exists, it overwrites their academic data but preserves their password. If the SEN is new, it creates a new row.

3. File Structure (To be generated by IDE)
index.html: The main student landing page. Must strictly use the exact CSS and UI design from the provided index (1).html file. All admin features and hardcoded data arrays are removed from this file.

dashboard.html: The personalized student result view. Populated dynamically upon successful login, maintaining the original UI aesthetic.

admin-hidden.html: The secret admin portal.

Requires admin password (Gopal@Amity).

Features: File upload input for raw .xlsx files, and a "Clear Password" utility for specific SENs.

script.js: Frontend logic. Handles login routing, intercepts the Excel file upload, uses SheetJS to consolidate the data into a clean JSON array, and sends it to the GAS backend.

backend.gs: The Google Apps Script running on Google Drive. Receives the JSON payload and performs the database overwrites.

4. Logic & Workflow Concepts
A. Admin Raw Excel Upload & CRUD Operations

Admin logs into admin-hidden.html.

Admin uploads the raw semester result .xlsx file.

Phrase & Filter (Frontend): script.js reads the file via SheetJS, extracts the relevant columns (SEN, Course Code, Grades, Credits, etc.), calculates CGPA if necessary, and formats it into a clean JSON array.

Database Sync (Backend): The JSON array is sent via POST to the GAS URL.

GAS Upsert Execution:

GAS reads the Google Sheet.

For each student in the JSON payload, it searches for their SEN.

If found: It overwrites columns related to grades, courses, and registered credits. It explicitly skips the "Password" column to keep existing logins intact.

If not found: It appends a completely new row for that student.

B. First-Time Login & Password Creation

Student enters SEN on index.html and types pwd as the password.

UI shifts to "Create Password" mode.

script.js sends SEN and new password to GAS.

GAS updates that specific student's row in the Google Sheet with the hashed/stored password.

C. Returning Student Login

Student enters SEN and custom password.

GAS validates against the Google Sheet.

If valid, GAS returns only that student's consolidated data row.

Frontend renders dashboard.html.

D. Admin Password Reset (The 'Delete' in CRUD)

Admin enters a student's SEN in admin-hidden.html and clicks "Reset".

GAS clears the cell in the "Password" column for that SEN.

The student is now forced to use the pwd flow on their next visit.
